> **本文档把备赛拆成可验证的阶段，每个阶段都有明确的交付物和验收标准。**
> 三人队最大的风险不是技术难度，而是"一直在准备、从未跑通"。
> **因此每个里程碑都必须是"可运行/可验收"的，不能是"文档写完"。**

> **维护人**：A（系统集成）　|　**更新频率**：每两周

## 2. 研发阶段划分

> **总体策略**：先跑通，再提速，最后提精度。
> **理由**：现场初赛计分项中，"完成全流程"是拿分的前提。
> 一个能跑完但精度一般的机器人，得分远高于一个精度高但跑不完的机器人。

```
阶段0 准备     阶段1 方案冻结   阶段2 单元跑通   阶段3 全流程   阶段4 精度节拍   阶段5 冻结提交
  │              │                │               │              │                │
  ▼              ▼                ▼               ▼              ▼                ▼
规则消化      接口契约v1       能读码+能抓1个   6个物料完整    1环命中率       冻结main
合规自查      技术路线定       能放1个         搬运完成       3分钟内完成      匿名提交包
              BOM v1                                           稳定复现         答辩材料
```

## 5. 硬集成日制度（★三人队的生命线）

| 项 | 规定 |
|---|---|
| 频率 | **每两周一次**，阶段 2/3 期间建议每周 |
| 参与 | **三人必须全部到场** |
| 时长 | 半天以上 |
| 内容 | 把三人的东西**物理装到一起**，跑一次真实流程 |
| 输出 | 当次的问题清单 + 责任分配 + 下次集成日 |
| **延期** | ❌ **不允许**。若有人无法到场，改期但不可取消 |

**为什么这是生命线**：
本队 3 人，机械 1 人、电控 1 人、集成 1 人。**任何人掉队都会阻塞整条链路。**
而"各做各的直到最后才装"是必死模式——因为接口问题会集中爆发，且没有时间修。

**每次硬集成日的固定议程**

1. 各自汇报：上次以来做了什么、遇到什么
2. **装到一起，跑一次**
3. 记录**所有**失败点（不管多小）
4. 分派 Issue
5. 确定下次集成日

## 7. 风险与预案

> 详细风险登记见 [风险登记.md](风险登记.md)。此处只列时间相关风险。

| 风险 | 影响 | 预案 |
|---|---|---|
| 硬件选型迟迟不定 | 阶段 1 拖延，全部后移 | 设硬期限；先用手边现有器件搭原型 |
| 某一模块卡住 | 阻塞集成 | 硬集成日暴露；考虑降级方案 |
| 队员时间不足（课业冲突） | 进度不稳 | 提前排课表；关键路径集中在少数人 |
| 场地不可用（无法实测） | 精度优化无法验证 | 自建简易场地（2400×2400 喷绘布 + 亚克力圆环） |
| 精度始终达不到 | 得分受限 | 降级：保证 2–3 环，放弃 1 环 |
| 转盘行为与预期差异大 | 抓取失败 | 预留动态抓取方案；尽早实测 |
| 决赛"创新实践"现场出题 | 无准备 | 赛前专门演练现场设计-加工-集成 |
