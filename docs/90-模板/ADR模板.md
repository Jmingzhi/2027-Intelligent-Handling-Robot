# ADR 模板

> **文档定位**：ADR = **Architecture Decision Record**（架构决策记录）。
> 用于把"我们为什么这样决定"固定下来，**避免三人队反复推翻同一个决定**。
>
> **使用方式**：复制本文件到 `docs/50-决策记录/`，命名为 `ADR-XXXX-简短标题.md`，逐项填写。
> 填写指引见文末。
>
> **关联**：[决策记录 README](../50-决策记录/README.md) · [ADR-0001 示例](../50-决策记录/ADR-0001-采用折叠臂构型.md) · [实验记录模板.md](实验记录模板.md)

# 填写指引

## 什么时候需要写 ADR

> ⚠️ ADR 不是给"每个小决定"写的，否则会淹没重点。**符合以下任一条，就应写 ADR**：

| # | 条件 | 例子 |
|---|---|---|
| 1 | **涉及多人** | 接口约定、模块分工边界 |
| 2 | **不可逆或代价极高** | 选了某个主控、定了某个构型 |
| 3 | **影响接口** | 改了通信协议、改了坐标系 |
| 4 | **有多种合理选择** | 差速 vs 麦轮、单相机 vs 双相机 |
| 5 | **事后可能被反复质疑** | "为什么不用 XX 方案？" |
| 6 | **涉及合规判断** | 某个零件能不能买、某个结构算不算辅助装置 |

**不需要写 ADR 的情况**：代码风格、临时调试参数、纯执行性的实现细节。

## 状态的含义

| 状态 | 含义 | 能否修改正文 |
|---|---|---|
| **提议** | 讨论中，尚未拍板 | ✅ 可改 |
| **已接受** | 已拍板，团队须遵守 | ⚠️ 只可追加，不可篡改 |
| **已废弃** | 不再适用，且无替代 | ❌ 冻结 |
| **被取代** | 被更新的 ADR 替代 | ❌ 冻结，注明取代者 |

> ⚠️ **已接受的 ADR 正文不得篡改**。若决策变了，**新写一份 ADR**，
> 把旧的状态改为"被取代"。这样才保留了"我们当时怎么想的"这条信息。

## 写作要点

| # | 要点 | 说明 |
|---|---|---|
| 1 | **背景写问题，不写方案** | 读者要能独立理解"难在哪" |
| 2 | **决策要可验收** | 写"采用折叠臂，展开后臂展 ≥300 mm"，不写"采用折叠臂" |
| 3 | **备选至少 2 个** | 只有一个方案的 ADR 没有决策价值 |
| 4 | **负面后果必须诚实** | 只写优点的 ADR 会在实施时反噬 |
| 5 | **写明依据来源** | 是规则？实测？还是"感觉"？ |
| 6 | **写明触发条件** | 什么情况下这个决策会失效 |
| 7 | **写明复审日期** | 无复审日期的 ADR 会变成"永久真理" |

## 常见错误

| ❌ 错误做法 | ✅ 正确做法 |
|---|---|
| 只写结论，不写备选 | 列出对比表 |
| 把 ADR 当成"计划书" | ADR 只记决策，不记实施步骤 |
| 决策变了就改旧 ADR | 新写一份，旧的标"被取代" |
| 不写负面后果 | 诚实列出代价与风险 |
| 全凭感觉决策 | 标注依据来源与待实测项 |
| 编号不连续 | 严格递增，不复用编号 |

## 编号规则

```
ADR-0001  第一份
ADR-0002  第二份
...
```

> ⚠️ **编号一旦分配即不复用**。废弃的 ADR 也保留编号。
> 详见 [决策记录 README](../50-决策记录/README.md)。
