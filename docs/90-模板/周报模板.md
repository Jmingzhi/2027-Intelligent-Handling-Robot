# 周报模板

> **文档定位**：本模板用于三人队**每周**同步进度、暴露问题、对齐计划。
> 三人队的核心风险是"信息不同步 + 单人掉队阻塞全链路"。
>
> **使用方式**：复制本文件，命名为 `docs/60-项目管理/周报/YYYY-Www.md`（如 `2027-W08.md`），逐项填写。
> **提交时间**：每周固定时间（建议周日晚）提交，逾期视为未完成。
>
> **关联**：[里程碑.md](../60-项目管理/里程碑.md) · [风险登记.md](../60-项目管理/风险登记.md) · [待确认清单.md](../60-项目管理/待确认清单.md) · [会议记录模板.md](会议记录模板.md)

## 九、周报自检

- [ ] 三个角色的完成情况都已填写（不是只写自己）
- [ ] 每项完成事项都有**交付物链接或证据**（不能只写"做了 XX"）
- [ ] "未解决的问题"已如实填写
- [ ] 下周计划每项都有负责人与截止日期
- [ ] 里程碑偏差已分析，滞后项有追赶措施
- [ ] 风险部分已更新，新增风险已登记
- [ ] "需要队友配合的事项"写清了"要什么、何时要"

## 附：周报写作纪律

| # | 纪律 | 说明 |
|---|---|---|
| 1 | **只写事实，不写形容词** | ❌"进展顺利" → ✅"完成 X，实测 Y=Z" |
| 2 | **完成必须以交付物为准** | 代码合并、文档提交、实测数据落库才算完成 |
| 3 | **问题不藏** | 早暴露的问题成本最低 |
| 4 | **下周计划要可验收** | 不写"继续优化"，写"把 X 从 A 改到 B" |
| 5 | **必须提到队友依赖** | 三人队的瓶颈永远是接口，不是个人能力 |
| 6 | **准时提交** | 迟到的周报等于没有周报 |
