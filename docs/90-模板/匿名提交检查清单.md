# 匿名提交检查清单

> **文档定位**：本清单用于提交前的**去标识化自检**。
> 依据规则：任务命题文档中出现**校名、姓名、队名、地名、单位名、电话、特殊符号** → **文档成绩 0 分**；
> 且**不得修改模板现有标题**（改了同样判 0 分）。
>
> **使用方式**：每次更新 `release/submission/` 后**逐条打勾**，并运行自动检查脚本。
> **本清单必须签字确认后才能提交。**
>
> > ⚠️ **这是本仓库风险最高的一项**：其他问题是"少得分"，这一项是"直接 0 分"。
>
> **关联**：[合规检查表.md](../00-规则与命题/合规检查表.md) 第五部分 · [规则解读.md](../00-规则与命题/规则解读.md) 9.2 节 · `tools/check_anonymity.py` · [PR描述模板.md](PR描述模板.md)

## 二、双轨管理说明

> 💡 **核心机制**：内部文档（带身份信息，方便协作）与提交版（绝对匿名）**分开维护**，
> 提交版**从零重新生成**，而不是"把内部文档删删改改"。

```
┌─────────────────────────────────────────────────────────────────┐
│  内部版（本仓库开发分支，正常留存身份信息）                       │
│                                                                  │
│   docs/20-技术方案/        完整设计思路与技术方案                 │
│   docs/50-决策记录/        决策背景（含真实讨论过程）             │
│   docs/30-实验记录/        实验原始数据                           │
│   hardware/                CAD / BOM / 合规台账                   │
│   embedded/ vision/        源码                                   │
│                                                                  │
│   ✅ 可以写姓名、校名、队名、地点                                 │
│   ✅ 可以用 ★ ⚠️ 💡 等排版符号（便于阅读）                        │
│   ✅ 可以保留 TBD 与内部批注                                      │
└───────────────────────────────┬─────────────────────────────────┘
                                │
                    匿名化处理（重新生成，非删改）
                                │
                                ▼
┌─────────────────────────────────────────────────────────────────┐
│  提交版 release/submission/（绝对干净）                          │
│                                                                  │
│   任务命题文档.pdf                                                │
│   设计说明书.pdf                                                  │
│   答辩PPT.pptx                                                    │
│   ...                                                            │
│                                                                  │
│   ❌ 无校名/姓名/队名/地名/单位名/电话/邮箱                       │
│   ❌ 无装饰性特殊符号                                             │
│   ❌ 无元数据残留                                                 │
│   ❌ 无 TBD 残留                                                  │
│   ✅ 官方模板标题一字未改                                         │
└─────────────────────────────────────────────────────────────────┘
```

| 轨道 | 位置 | 分支 | 内容 | 检查要求 |
|---|---|---|---|---|
| **内部版** | 各开发目录 | `develop` / `feature/*` | 含身份信息，正常协作 | 常规评审 |
| **提交版** | `release/submission/` | `release/*` / `main` | 完全匿名 | ★ **每次更新后必须重跑匿名检查** |

### 2.1 双轨纪律

| # | 纪律 | 理由 |
|---|---|---|
| 1 | **提交版的文件从不直接复制自带姓名的内部文档** | 复制会带入元数据 |
| 2 | **匿名化是"重新生成"，不是"删删改改"** | 删改会残留元数据与修订记录 |
| 3 | **每次更新提交版后重新运行匿名检查** | 手工修改容易漏 |
| 4 | **提交版纳入版本控制** | 可追溯"提交了什么" |
| 5 | **提交前交叉检查** | 一人检查容易盲区，建议换人复核 |

## 三、匿名化方法

> ⚠️ **原则：重新生成，而非删改。**

| 做法 | ✅ 推荐 / ❌ 不推荐 | 理由 |
|---|---|---|
| 基于官方模板**重新撰写**内容 | ✅ | 无元数据残留 |
| 在内部文档上**删除**姓名 | ❌ | 残留修订记录、作者字段 |
| 用"查找替换"改校名 | ❌ | 可能残留格式信息；且容易漏 |
| 另存为 PDF 后**清空作者字段** | ✅ | 必须做 |
| 图片**重新导出**（去掉 EXIF） | ✅ | 必须做 |
| 复制粘贴到新文档 | ⚠️ | 会继承源文档样式，但元数据较干净；仍需检查 |
| 直接提交内部文档 | ❌ | 高危 |

### 3.1 推荐的匿名化流程

| 步骤 | 操作 | 工具 |
|---|---|---|
| 1 | 从**官方模板**新建文档 | Word / LaTeX 模板 |
| 2 | 从内部文档**搬运内容**（只搬文字/图表，不搬样式） | 手工 |
| 3 | 逐字核对**官方标题未改** | 人工 |
| 4 | 删除所有 `TBD` 与内部批注 | 查找替换 |
| 5 | 图片重新导出（去 EXIF） | 图像工具 |
| 6 | 清除文档元数据（文档检查器） | Word |
| 7 | 导出 PDF，**清空 PDF 作者字段** | PDF 工具 |
| 8 | 运行自动检查脚本（`--strict`） | `tools/check_anonymity.py` |
| 9 | 人工复核（换人做） | 队友 |
| 10 | 打包，检查包内无临时文件 | 手工 |
| 11 | 再次运行检查脚本 | 脚本 |

### 3.2 特殊符号的处理

| 情形 | 处理 |
|---|---|
| 本仓库内部文档大量使用 `★ ⚠️ 💡` | ⚠️ **提交版必须全部移除或替换** |
| 表格线 `─ │ ┌` | 一般属正常排版，但**建议改为标准 Markdown/Word 表格**避免争议 |
| 数学符号（α β σ ≤ ≥） | 一般可接受（与内容有关） |
| 箭头 `→` | 若用于表示流程，一般可接受；若为装饰，移除 |

> ⚠️ 规则原文是"**与文档内容无关的**特殊符号"。
> 判断标准是"是否与内容有关"。**拿不准的一律去掉**。

## 四、自动检查命令

### 4.1 标准检查（提交前必做）

```bash
python tools/check_anonymity.py --path release/submission --strict
```

| 退出码 | 含义 | 处理 |
|---|---|---|
| `0` | 未发现高危命中 | ✅ 通过 |
| `1` | **发现高危命中** | ❌ **必须修复后重跑** |
| `2` | 参数或配置文件错误 | ⚠️ 检查命令 |

### 4.2 相关命令

```bash
# 查看词库（确认当前检查覆盖了哪些关键词）
python tools/check_anonymity.py --list

# 检查内部文档目录（提示性检查，不阻断）
python tools/check_anonymity.py --path "docs/00-规则与命题"

# 检查单个文件
python tools/check_anonymity.py --path release/submission/任务命题文档.md

# 使用自定义词库
python tools/check_anonymity.py --path release/submission --config my_wordlist.json
```

### 4.3 检出类别说明

| 类别 | 检出方式 | 级别 | 说明 |
|---|---|---|---|
| `school` | 校名关键词（含英文缩写、校园域名） | **高危** | 词库可配置 |
| `identity` | 姓名 / 队名 / 组长等标记词 + 真实姓名列表 | **高危** | — |
| `contact` | 手机号、邮箱、QQ 号（正则） | **高危** | — |
| `marker` | 装饰性特殊符号成组出现 | **高危** | — |
| `weak` | 过于宽泛的弱关键词（如"大学""学院"） | 仅提示 | ⚠️ **不判失败，需人工判断** |

> ⚠️ **脚本通过 ≠ 人工可以免检**。
> 脚本只能查"词"，查不出"由上下文推断出的身份"（例如"我们学校在华南地区"）。
> **脚本 + 人工复核，两者都不可省。**

### 4.4 CI 门禁

| 项 | 说明 |
|---|---|
| Workflow | `.github/workflows/anonymity-check.yml` |
| 触发 | 提交至 `main` / `release/*` / 涉及 `release/submission/` 的 PR |
| 作用 | 自动扫描并阻断含高危命中的提交 |
| ⚠️ 注意 | CI 通过不替代本地 `--strict` 检查，也不替代人工复核 |
