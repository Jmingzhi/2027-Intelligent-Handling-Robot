# 合规检查表

> **用途**：本赛项有大量"违反即取消资格 / 成绩归零"的红线。此表用于**在设计、采购、装配、提交的每个阶段逐条自查**。
> **使用方式**：每次阶段评审前打印或打开此表，逐条打勾；不确定的一律标记为「待确认」并尽快向裁判/组委会澄清。
> **关联**：[规则解读.md](规则解读.md) · [../60-项目管理/风险登记.md](../60-项目管理/风险登记.md) · `hardware/compliance/`

---

## 使用说明

- 状态标记：`✅ 符合` / `❌ 不符合` / `⚠️ 待确认` / `— 不适用`
- **每次评审必须有签字记录**，登记在文末的评审记录表。
- **任何 `⚠️ 待确认` 项在赛前必须清零**，否则视为风险。

# 第一部分：采购与自制合规（最易致命）

> 规则原文：「除标准件外，非标零件应**自主设计和制造**，**不允许使用购买的成品或采用成品套件拼装而成**。」
> 违规后果：**取消比赛资格**。

## 1.1 判定原则

| 类别 | 是否允许购买 | 说明 |
|---|---|---|
| **标准件** | ✅ 允许 | 螺钉、螺母、垫圈、轴承、卡簧、销、弹簧、齿轮（标准系列）、同步带、链条、型材、光轴、直线轴承、联轴器、标准舵机、标准电机、标准传感器模块 |
| **成品套件/成品模块** | ❌ 禁止 | 成品机器人底盘、成品机械臂、成品套件车（如"XX 机器人套件"）、成品抓取模块 |
| **非标结构件** | ❌ 禁止购买，必须自制 | 底板、支架、连接件、夹爪、料仓、外壳、转接件 |
| **标准件改制的非标件** | ⚠️ 需评估 | 在标准件基础上自行加工改制的零件，一般可接受，但**保留加工记录和照片** |

## 1.2 灰色地带（需向裁判确认）

| 情形 | 风险判断 | 应对 |
|---|---|---|
| 购买成品舵机支架（金属/3D打印件） | ⚠️ **高风险** —— 通常属于非标结构件 | 尽量自制；如必须用，保留证据说明其为通用标准配件 |
| 购买成品履带/轮胎 | ✅ 通常视为标准件 | 保留购买记录 |
| 购买成品 PCB 模块（如电机驱动板、降压模块） | ⚠️ 需评估 | 电控模块一般可接受，但**建议尽量自制 PCB**（也利于创意分） |
| 购买成品码盘/编码器 | ✅ 标准件 | — |
| 购买成品丝杆+螺母副 | ✅ 标准件 | 你的抓手已用此方案，合规 |
| 购买成品同步带轮 | ✅ 标准件 | — |
| 使用开源项目的 3D 打印件图纸 | ⚠️ **高风险** —— 非"自主设计" | **必须自己重新设计**，不要直接下载打印 |
| 购买成品亚克力切割件 | ❌ 非标结构件 | 自行设计并加工 |
| 3D 打印服务代打（自己设计） | ✅ 合规 —— 设计是自己的 | 保留设计文件（.stl/.step）和打印记录 |

## 1.3 合规台账要求

**每一个非标准件都必须在 [hardware/compliance/](../../hardware/compliance/) 中登记**，字段见该目录下 README。

**建议做法**：
1. 设计阶段就标注每个零件的"来源"：`自制-3D打印` / `自制-机加工` / `标准件-外购` / `⚠️待确认`
2. BOM 表中增加「来源」列，与此台账对应
3. **保留证据**：设计源文件、加工照片、购买订单截图（标准件）

## 1.4 自查清单

- [ ] 全部非标零件均为自主设计（有设计源文件可证）
- [ ] 未使用任何成品机器人底盘 / 成品机械臂 / 成品套件
- [ ] 未直接使用他人开源项目的结构件图纸（或已完全重新设计）
- [ ] BOM 每行都标注了「来源」
- [ ] `hardware/compliance/` 台账已登记全部非标件
- [ ] 已保留加工过程照片（利于"制造精细"评分）
- [ ] 灰色地带项已向裁判/组委会书面确认
- [ ] 无「成品套件拼装」嫌疑

# 第二部分：外形尺寸合规

> 规则原文：「搬运机器人（含机械手臂）最大外形尺寸满足**铅垂方向投影不大于边长 300 mm 的正方形**，**高度不超过 400 mm**，包括**所有软质线路**等都必须在此尺寸范围内方可参赛。允许机械臂结构为**可折叠形式**，但**出发后方可自行展开**，**展开后尺寸不受上述限制**。」
> 违规后果：**取消比赛资格**。

## 2.1 自查清单

- [ ] **折叠态**（含机械臂）铅垂投影 ≤ **300 × 300 mm**
- [ ] **折叠态**高度 ≤ **400 mm**
- [ ] 测量时**包含所有软质线路**（线材不能甩在外面）
- [ ] 机械臂处于"出发前状态"时才测量（不能靠展开后尺寸糊弄）
- [ ] 机械臂为**可折叠**形式，且**折叠态能保持**（不能自己弹开）
- [ ] 展开动作是**出发后自行展开**（不能靠人手动展开）
- [ ] 尺寸测量有**照片/视频记录**，登记在 [../05-场地与标定/](../05-场地与标定/)

## 2.2 测量方法要求

| 项 | 方法 |
|---|---|
| 投影 | 用直角尺/投影板贴地，量最大外包络矩形；建议做**300×300 mm 检具框**（纸板即可）直接套 |
| 高度 | 平板 + 高度尺/直尺，量最高点到地面 |
| 线材 | 把线束按实际运行状态的固定方式绑好后再测 |
| 记录 | **拍照片**（含尺度参照物），存 `test/acceptance/` |

> ⚠️ **检录时会现场测量**，且"若已经参加比赛，发现或投诉并情况属实取消比赛成绩"。**赛前必须反复测量确认。**

# 第三部分：电控与电源合规

## 3.1 自查清单

- [ ] 只使用**一个**电源（电池组算一个电源；并联的多节电池算一个电源组）
- [ ] 电源**装在机器人内部**
- [ ] 电源**不是液体电池**、不含对环境有腐蚀及污染的物质
- [ ] 比赛中（**含调试期间**）**不更换电源**
- [ ] 电源容量足够支撑 **3 分钟运行 + 3 分钟调试**，且有余量
- [ ] 有**电量指示**或低压保护（避免中途欠压停机）
- [ ] **无任何遥控接收装置**（遥控器/无线遥控模块一律不能有）
- [ ] 若有无线通信模块，**仅用于与笔记本的数据通信**，无遥操作能力
- [ ] 笔记本通信方式明确（USB / WiFi / 蓝牙），且**运行中人不接触笔记本**

## 3.2 一键启动

- [ ] 有明确的**「启动」标识**按钮
- [ ] **只有这一个**启动按钮（不能有隐藏的第二个）
- [ ] 按钮**不被任何物品遮挡**
- [ ] 按下一次即启动全流程（不需多次操作）
- [ ] 启动后**无法再通过人手干预**

## 3.3 任务码显示装置

- [ ] 安装在机器人**上部醒目位置**
- [ ] **亮光显示**（自发光的屏/数码管/点阵）
- [ ] **不被任何物体遮挡**（含机械臂展开后也不能挡）
- [ ] 字高 **≥ 12 mm**（要实测字符实际高度）
- [ ] 能显示**完整任务码**（4 组三位数 + 加号，共 15 字符）
- [ ] 能显示**抓取正确次数**和**放置正确次数**
- [ ] 调试期间**始终显示**（规则解析版要求"比赛过程中始终显示任务码"）

## 3.4 补光与遮挡

- [ ] **不对场地构成遮挡**（无遮光罩/挡板）
- [ ] 补光**仅垂直向下**（无侧向光源、无斜射光源）
- [ ] 主动光源不影响其他队伍（赛场纪律）

# 第四部分：运行行为合规（现场注意）

| # | 规则 | 应对 |
|---|---|---|
| 1 | 一键启动后不得再接触机器人（含笔记本）或物料 | 启动前完成全部自检 |
| 2 | 机器人停止运行 15 秒本轮结束 | 任何等待逻辑都要有超时保护 |
| 3 | 物料底面触地后再移动，本轮结束 | 落点一次到位，软件不得"微调" |
| 4 | 铅垂投影越出车道（机械臂除外），本轮结束 | 路径规划留边界余量；抓取靠臂伸出 |
| 5 | 掉落物料不得自行取出 | 软件要有掉料检测并继续执行 |
| 6 | 不允许用手爪夹持物料运送 | 抓取后必须放入本体料仓 |
| 7 | 物料未放到机器人上不能去下一区域（本区域内不受限） | 增加"物料已上机"确认信号 |
| 8 | 原地高速打滑可能被判终止；破坏场地取消资格 | 限制打滑（电流限制/防滑轮/加速度限制） |

- [ ] 上位机/固件中所有等待均设置超时（≤3 秒级）
- [ ] 有"物料已上机"确认机制（传感器或视觉）
- [ ] 路径规划的边界安全余量已实测（建议 ≥ 40 mm）
- [ ] 未采用"夹持运送"策略
- [ ] 有防打滑措施

# 第五部分：提交文档合规（最高危，直接 0 分）

> 规则原文：若**修改文档内现有标题**、**文档雷同**、文档中出现**地名、单位名、姓名、电话号码**以及各种与文档内容无关的**特殊符号**等情况，本队任务命题文档成绩均为 **0 分**。
> 另：「参赛队提交的文档雷同，文档中出现**校名、姓名、队名、特殊标记符号**等，文档成绩为 0 分。」

## 5.1 绝对禁止出现的内容

| 类别 | 示例 | 检查方式 |
|---|---|---|
| **校名** | 华南理工大学、SCUT、scut.edu.cn | 脚本 + 人工 |
| **姓名** | 全体队员、指导教师姓名 | 脚本 + 人工 |
| **队名** | 任何自定义队名 | 人工 |
| **地名** | 广州、广东、天河区等 | 脚本 + 人工 |
| **单位名** | 学院名、实验室名、公司名 | 脚本 + 人工 |
| **电话号码** | 手机号、固话 | 脚本（正则 `1[3-9]\d{9}`） |
| **邮箱** | QQ 邮箱、学校邮箱 | 脚本（正则） |
| **QQ/微信号** | — | 人工 |
| **特殊符号** | ★☆●◆■▲※→ 等装饰性符号成组出现 | 脚本（低置信度警告） |

## 5.2 提交前必做

- [ ] 文档**标题一个字都没改**（对照官方模板逐字核对）
- [ ] 无校名、无姓名、无队名、无地名、无单位名、无电话、无邮箱
- [ ] 无装饰性特殊符号（表格线、项目符号属正常排版，不算）
- [ ] **文档排版规范**已检查（占 25 分）
- [ ] 文档内容质量达到要求（占 75 分）
- [ ] 文档**与其他队伍不雷同**（本队内部三人之间也不能雷同）
- [ ] 已运行 `python tools/check_anonymity.py --path release/submission --strict` 且**无高危命中**
- [ ] 已运行 CI 的 anonymity-check 且通过
- [ ] 输出的**文件属性/元数据**已清除作者信息（Word「文档检查器」→ 删除个人信息）
- [ ] PDF 导出的**作者字段**已清空（检查 PDF 元数据）
- [ ] 文件名本身不含姓名/校名（规则要求压缩包命名为「负责人姓名+参赛赛项+手机号」，**仅压缩包文件名如此，内部文档不能有**）
- [ ] 压缩包内**无临时文件、无 `.bak`、无隐藏文件**

## 5.3 双轨管理机制

```
内部版（本仓库，带姓名/校名，正常留存）
        │
        ├── docs/20-技术方案/          → 完整设计思路
        ├── docs/50-决策记录/          → 决策背景
        └── ...
        │
        ▼  匿名化处理（人工 + 脚本）
release/submission/（提交版，绝对干净）
        ├── 任务命题文档.pdf
        ├── 设计说明书.pdf
        ├── 答辩PPT.pptx
        └── ...
```

- [ ] `release/submission/` 内的文件**从未**直接复制自带姓名的内部文档
- [ ] 匿名化是**重新生成**，而非"删删改改"（避免残留元数据）
- [ ] 每次更新提交版后**重新运行**匿名检查
