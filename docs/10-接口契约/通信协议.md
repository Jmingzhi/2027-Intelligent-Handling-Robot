# 通信协议

> **本文档定义机器人内部各模块之间、以及与笔记本之间的通信协议。**
> 硬件（主控型号、是否用上位机）尚未确定，因此本文档先固定**帧格式、命令集、错误处理**这些与硬件无关的部分。
>
> **关联**：[ICD-机械电气接口.md](ICD-机械电气接口.md) · [任务码定义.md](任务码定义.md) · [坐标系与标定约定.md](坐标系与标定约定.md)

## 0. 状态与约定

| 项 | 值 |
|---|---|
| 协议版本 | **v0.1（草案）** |
| 硬件依赖 | 尽量与硬件解耦；串口参数待定 |
| 字节序 | **小端（Little-Endian）** —— 与 STM32/ARM 一致，全局统一 |
| 长度单位 | mm |
| 角度单位 | 度（°），0.01° 精度 |
| 时间单位 | ms |
| 校验 | **CRC-16/CCITT**（多项式 0x1021，初值 0xFFFF） |

> ⚠️ **字节序必须全局统一**。三人队最常见的 bug 来源之一就是一边小端一边大端，
> 表现为"数据能收到但值是乱的"。

## 2. 通用帧格式

### 2.1 帧结构

```
┌──────┬──────┬──────┬──────────┬──────────┬──────────┬──────┐
│ HEAD │ ADDR │ CMD  │ LEN      │ PAYLOAD  │ CRC16    │ TAIL │
│ 2 B  │ 1 B  │ 1 B  │ 1 B      │ 0-255 B  │ 2 B      │ 1 B  │
└──────┴──────┴──────┴──────────┴──────────┴──────────┴──────┘
```

| 字段 | 长度 | 说明 |
|---|---|---|
| `HEAD` | 2 B | 固定 **`0xAA 0x55`** |
| `ADDR` | 1 B | 目标地址（见 2.2） |
| `CMD` | 1 B | 命令码（见第 3 节） |
| `LEN` | 1 B | `PAYLOAD` 字节数，0–255 |
| `PAYLOAD` | 0–255 B | 数据体 |
| `CRC16` | 2 B | 对 `ADDR + CMD + LEN + PAYLOAD` 计算 |
| `TAIL` | 1 B | 固定 **`0x5A`** |

**总长度** = 2 + 1 + 1 + 1 + LEN + 2 + 1 = **LEN + 8 字节**

### 2.2 地址分配

| ADDR | 设备 | 状态 |
|---|---|---|
| `0x00` | 广播 | — |
| `0x01` | 主控 MCU | ✅ 固定 |
| `0x10` | 底盘驱动 | ⬜ 待定 |
| `0x20` | 机械臂控制器 | ⬜ 待定 |
| `0x30` | 视觉模块 | ⬜ 待定 |
| `0x40` | 任务码显示装置 | ⬜ 待定 |
| `0x50` | 料仓检测 | ⬜ 待定 |
| `0xF0` | 笔记本（调试） | — |

### 2.3 CRC-16/CCITT 参考实现

```c
/* CRC-16/CCITT-FALSE: poly=0x1021, init=0xFFFF, no reflect, no xorout */
uint16_t crc16_ccitt(const uint8_t *data, uint16_t len)
{
    uint16_t crc = 0xFFFF;
    for (uint16_t i = 0; i < len; i++) {
        crc ^= (uint16_t)data[i] << 8;
        for (uint8_t b = 0; b < 8; b++) {
            crc = (crc & 0x8000) ? (uint16_t)((crc << 1) ^ 0x1021)
                                 : (uint16_t)(crc << 1);
        }
    }
    return crc;
}
```

> ⚠️ **B 和 C 双方必须使用同一份 CRC 实现**（建议放在 `embedded/shared/` 下共用）。
> 两边各写一份是 bug 温床。

## 3. 命令集

### 3.1 系统类

| CMD | 名称 | 方向 | PAYLOAD | 说明 |
|---|---|---|---|---|
| `0x01` | `HEARTBEAT` | 双向 | `uint32 timestamp_ms` | 心跳，检测链路存活 |
| `0x02` | `PING` | → | — | 探测 |
| `0x03` | `PONG` | ← | — | 应答 |
| `0x04` | `ACK` | ← | `uint8 acked_cmd` | 确认收到 |
| `0x05` | `NACK` | ← | `uint8 nacked_cmd, uint8 err_code` | 拒绝/错误 |
| `0x06` | `RESET` | → | — | 软复位（**比赛运行中禁用**） |

### 3.2 任务与状态类

| CMD | 名称 | 方向 | PAYLOAD | 说明 |
|---|---|---|---|---|
| `0x10` | `START_MISSION` | 主控→全部 | — | **一键启动**触发后广播，进入任务流程 |
| `0x11` | `MISSION_STATE` | 主控→显示 | `uint8 state_id` | 上报当前状态机状态 |
| `0x12` | `EMERGENCY_STOP` | 主控→全部 | — | 紧急停止 |
| `0x13` | `TASK_CODE_SET` | 主控→显示 | `char[15]` | 下发任务码字符串（如 `"156+123+516+231"`） |
| `0x14` | `STATS_UPDATE` | 主控→显示 | `uint8 grasp_ok, uint8 place_ok` | 下发统计计数 |

### 3.3 视觉类

| CMD | 名称 | 方向 | PAYLOAD | 说明 |
|---|---|---|---|---|
| `0x20` | `QR_RESULT` | 视觉→主控 | `uint8 status, char[15] code` | 二维码识别结果；`status`: 0=失败 1=成功 |
| `0x21` | `TARGET_QUERY` | 主控→视觉 | `uint8 color` | 请求指定颜色物料的位置 |
| `0x22` | `TARGET_RESULT` | 视觉→主控 | `int16 x, int16 y, uint8 confidence` | 物料位置（mm，坐标系见约定文档） |
| `0x23` | `RING_QUERY` | 主控→视觉 | `uint8 zone_id, uint8 ring_id` | 请求指定圆环的位置 |
| `0x24` | `RING_RESULT` | 视觉→主控 | `int16 x, int16 y, uint8 confidence` | 圆环位置 |
| `0x25` | `CALIB_CMD` | 主控→视觉 | `uint8 action` | 标定指令（0=开始 1=保存 2=载入） |

### 3.4 底盘类

| CMD | 名称 | 方向 | PAYLOAD | 说明 |
|---|---|---|---|---|
| `0x30` | `SET_VELOCITY` | 主控→底盘 | `int16 vx, int16 vy, int16 omega` | 速度指令（mm/s, mm/s, 0.01°/s） |
| `0x31` | `MOVE_TO` | 主控→底盘 | `int16 x, int16 y, int16 theta` | 位置指令（mm, mm, 0.01°） |
| `0x32` | `STOP` | 主控→底盘 | `uint8 mode` | 停止（0=滑行 1=急停） |
| `0x33` | `ODOM_REPORT` | 底盘→主控 | `int16 x, int16 y, int16 theta` | 里程计上报 |
| `0x34` | `SET_MODE` | 主控→底盘 | `uint8 mode` | 控制模式（速度/位置） |

### 3.5 机械臂类

| CMD | 名称 | 方向 | PAYLOAD | 说明 |
|---|---|---|---|---|
| `0x40` | `ARM_HOME` | 主控→臂 | — | 回零位 |
| `0x41` | `ARM_MOVE_JOINT` | 主控→臂 | `uint8 n, int16 angle[]` | 关节角指令（0.01°） |
| `0x42` | `ARM_MOVE_POSE` | 主控→臂 | `int16 x, int16 y, int16 z, int16 rx` | 末端位姿指令 |
| `0x43` | `ARM_GRIP` | 主控→臂 | `uint8 action` | 夹爪（0=张开 1=闭合 2=保持） |
| `0x44` | `ARM_STATUS` | 臂→主控 | `uint8 status, uint8 moving` | 状态上报 |
| `0x45` | `ARM_DONE` | 臂→主控 | `uint8 cmd_id` | 动作完成通知 |

### 3.6 料仓类

| CMD | 名称 | 方向 | PAYLOAD | 说明 |
|---|---|---|---|---|
| `0x50` | `STOW_STATUS` | 料仓→主控 | `uint8 occupied_mask` | 各位表示每个格位是否有物料 |
| `0x51` | `STOW_QUERY` | 主控→料仓 | — | 查询料仓状态 |

> ⚠️ `STOW_STATUS` 是**规则硬需求**的支撑：「物料没有放置到搬运机器人上不能向下一个区域运行」。

## 4. 典型交互时序

### 4.1 启动到读码

```
主控                    显示                视觉              底盘
 │                       │                   │                 │
 │──START_MISSION───────►│                   │                 │
 │──MISSION_STATE(READ_QR)►                  │                 │
 │──MOVE_TO(二维码板前)──┼───────────────────┼────────────────►│
 │                       │                   │                 │
 │◄──────────────────────────────────────────┤ TARGET 到位      │
 │──QR 请求─────────────┼──────────────────►│                 │
 │◄─QR_RESULT(成功,码)──┼───────────────────┤                 │
 │──TASK_CODE_SET────────►│                  │                 │
 │──STATS_UPDATE(0,0)────►│                  │                 │
 │──MOVE_TO(原料区)──────┼───────────────────┼────────────────►│
```

### 4.2 抓取并上机（关键：必须确认在位）

```
主控                    视觉                机械臂            料仓
 │                       │                   │                 │
 │──TARGET_QUERY(颜色)──►│                   │                 │
 │◄─TARGET_RESULT(x,y)───┤                   │                 │
 │──ARM_MOVE_POSE(抓取位)┼──────────────────►│                 │
 │◄─ARM_DONE─────────────┼───────────────────┤                 │
 │──ARM_GRIP(闭合)───────┼──────────────────►│                 │
 │──ARM_MOVE_POSE(料仓位)┼──────────────────►│                 │
 │──ARM_GRIP(张开)───────┼──────────────────►│                 │
 │──STOW_QUERY───────────┼───────────────────┼────────────────►│
 │◄─STOW_STATUS(mask)────┼───────────────────┼─────────────────┤
 │  若对应位为 1 → 才允许前往下一区域                           │
 │  若为 0 → 重试，禁止移动                                     │
 │──STATS_UPDATE(grasp_ok++)►（显示）                           │
```

> ⚠️ **这个"确认在位才移动"的逻辑是规则硬要求，必须实现。**

## 5. 错误处理

### 5.1 错误码

| 码 | 名称 | 含义 | 处理 |
|---|---|---|---|
| `0x00` | `ERR_NONE` | 无错误 | — |
| `0x01` | `ERR_CRC` | CRC 校验失败 | 丢弃帧，请求重发 |
| `0x02` | `ERR_TIMEOUT` | 响应超时 | 重试 ≤3 次 |
| `0x03` | `ERR_BAD_CMD` | 未知命令 | 回 NACK |
| `0x04` | `ERR_BAD_PARAM` | 参数越界 | 回 NACK |
| `0x05` | `ERR_BUSY` | 设备忙 | 稍后重试 |
| `0x06` | `ERR_NOT_READY` | 设备未就绪 | 等待 |
| `0x07` | `ERR_QR_FAIL` | 二维码识别失败 | 重试读码 |
| `0x08` | `ERR_TARGET_LOST` | 目标丢失 | 重新搜索 |
| `0x09` | `ERR_GRIP_FAIL` | 抓取失败 | 重新定位 |
| `0x0A` | `ERR_STOW_FAIL` | 物料未上机 | **禁止移动**，重试 |
| `0x0B` | `ERR_LOW_BATTERY` | 低压告警 | 立即返回启停区 |
| `0x0C` | `ERR_COLLISION` | 碰撞/堵转 | 停止并上报 |

### 5.2 重试与退避

| 场景 | 策略 |
|---|---|
| CRC 错误 | 立即重发，≤3 次 |
| 响应超时 | 等待 50 ms 重发，≤3 次，指数退避至 400 ms |
| 连续失败 | 上报主控，进入错误处理分支 |
| 运行中总超时 | 单状态超时 ≤ **3 s**（规则：停止 15 s 本轮结束，需留足余量） |

> ⚠️ **所有等待必须有超时**。这是一个"停止 15 秒就结束比赛"的赛项。

## 6. 调试通道

| 项 | 约定 |
|---|---|
| 接口 | USB CDC / UART |
| 波特率 | TBD（建议 921600 或 USB 全速） |
| 用途 | 日志输出、参数配置、数据记录 |
| **禁止** | **任何形式的控制指令**（规则：不允许遥控） |

> ⚠️ **规则明确不允许任何方式的遥控**，但允许与笔记本通信。
> **实现时必须确保：笔记本只能"读"（日志/数据）和"配置参数"，不能"控制动作"。**
> 建议：调试协议（`0xF0` 地址）**只开放只读查询与参数写入**，不提供运动控制命令。
> 这一点建议写入代码评审检查项。

### 6.1 日志格式建议

```
[  1234ms] [STATE] GOTO_RAW1 -> PICK_B1
[  1250ms] [VISION] TARGET_QUERY color=1 -> (312, -85) conf=0.93
[  1890ms] [ARM] MOVE_POSE done in 620ms
[  2100ms] [STOW] mask=0b001 -> allow move
[  2110ms] [STATS] grasp_ok=1 place_ok=0
```

> 💡 **日志是赛后复盘和"为什么没得分"的唯一依据**，务必结构化输出并保存。

## 8. 共享代码约定

**通信协议的收发实现必须只有一份**，放在：

```
embedded/shared/
├── protocol.h          # 帧格式、命令码、错误码定义
├── protocol.c          # 打包/解包/CRC
├── protocol.py         # Python 侧实现（视觉/上位机/tools 使用）
└── test_protocol.py    # 单元测试（含 CRC 测试向量）
```

> ⚠️ **三方（固件、视觉 Python、tools）必须引用同一份定义**，不得各自复制粘贴。
> 若语言不同，用**代码生成**或**共享的常量表**保证一致，并在 CI 中校验两边的命令码一致。

### 8.1 CRC 测试向量（用于交叉验证）

| 输入（hex） | 期望 CRC16 |
|---|---|
| `01 01 00` | 待计算后填入 |
| `31 32 33 34 35 36 37 38 39` | `0x29B1`（"123456789" 标准测试向量） |

> ⚠️ `"123456789"` 的 CRC-16/CCITT-FALSE 结果 **必须等于 `0x29B1`**。
> **这是验证两边实现一致的黄金测试向量，务必加入单元测试。**
