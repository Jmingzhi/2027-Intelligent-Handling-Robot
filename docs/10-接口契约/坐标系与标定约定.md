# 坐标系与标定约定

> **为什么这份文档至关重要**：三人队最经典的 bug 是"一个用 mm 一个用 m"、"一个顺时针为正一个逆时针为正"、
> "相机坐标没转换就直接发给底盘"。这类错误表现为"机器人往反方向走"、"放置位置整体偏移"，
> 排查一次要花一整天。
>
> **本文档定义全部坐标系、正方向、单位、以及相互转换的约定。任何模块必须严格遵守。**
>
> **关联**：[ICD-机械电气接口.md](ICD-机械电气接口.md) · [通信协议.md](通信协议.md) · [任务码定义.md](任务码定义.md)

---

## 0. 全局约定（无例外）

| 项 | 约定 | 违反后果 |
|---|---|---|
| **长度单位** | **毫米（mm）**，全局唯一 | 偏移 1000 倍 |
| **角度单位** | **度（°）**，传输时用 0.01° 整数 | 旋转错乱 |
| **角度正方向** | **逆时针为正（右手法则）** | 机器人反向旋转 |
| **坐标系手性** | **右手系** | 镜像错误 |
| **X 轴** | 见各坐标系定义 | — |
| **Y 轴** | 见各坐标系定义 | — |
| **Z 轴** | **向上为正** | 高度算错 |
| **姿态角 θ** | 绕 Z 轴，X 轴转向 Y 轴为正 | — |
| **字节序** | 小端（见通信协议） | 数据乱码 |
| **坐标保留位** | 全部用 `int16`（±32767 mm 足够） | — |

> ⚠️ **禁止**在任何模块内使用 cm 或 m。若需显示给用户，仅在 UI 层转换。

## 1. 坐标系总览

```
┌─────────────────────────────────────────────────────────────────────┐
│  W 世界坐标系（World / Field）                                       │
│     固定在比赛场地上，原点在场地一角，不随机器人移动                    │
│                                                                     │
│   ┌───────────────────────────────────────────────────────────┐    │
│   │  F 场地坐标系（Field）                                     │    │
│   │     同上，用于存放场地元素坐标（启停区/圆环/二维码板）        │    │
│   │                                                           │    │
│   │      ┌──────────────────────┐                             │    │
│   │      │  R 机器人坐标系（Robot）│  ← 随机器人移动           │    │
│   │      │  原点在机器人几何中心   │                           │    │
│   │      │  或底盘旋转中心        │                           │    │
│   │      │                      │                             │    │
│   │      │   ┌────────────┐     │                             │    │
│   │      │   │ C 相机坐标系 │     │                             │    │
│   │      │   │ 原点在光心  │     │                             │    │
│   │      │   └────────────┘     │                             │    │
│   │      │                      │                             │    │
│   │      │   ┌────────────┐     │                             │    │
│   │      │   │ A 机械臂基座 │     │                             │    │
│   │      │   │ 坐标系      │     │                             │    │
│   │      │   └────────────┘     │                             │    │
│   │      └──────────────────────┘                             │    │
│   └───────────────────────────────────────────────────────────┘    │
└─────────────────────────────────────────────────────────────────────┘
```

| 代号 | 名称 | 原点 | 固定于 | 主要使用者 |
|---|---|---|---|---|
| **W / F** | 世界/场地坐标系 | 场地**左下角**（待实测确认方向） | 场地 | 路径规划、场地元素登记 |
| **R** | 机器人坐标系 | 机器人**底盘旋转中心**在底面的投影 | 机器人 | 里程计、运动控制 |
| **C** | 相机坐标系 | 相机**光心** | 机器人 | 视觉识别 |
| **A** | 机械臂基座坐标系 | 机械臂**基座中心**在安装面的投影 | 机器人 | 机械臂运动学 |
| **P** | 像素坐标系 | 图像**左上角** | 图像 | 视觉内部 |
| **T** | 工具/末端坐标系 | 夹爪**夹持中心** | 机械臂末端 | 抓取放置 |

## 2. 各坐标系详细定义

### 2.1 场地坐标系 F（World/Field）

```
        Y ↑
          │
          │        ┌─────────────────────────┐
          │        │                         │
          │        │      比赛场地            │
          │        │      2400 × 2400 mm     │
          │        │                         │
          │        │                         │
          │        └─────────────────────────┘
          │
          └──────────────────────────────────► X
        (0,0)
```

| 项 | 定义 |
|---|---|
| 原点 | 场地**左下角**（俯视图） |
| **X 轴** | 沿场地一条边，**向右为正** |
| **Y 轴** | 沿场地另一条边，**向上（远离观察者）为正** |
| **Z 轴** | **垂直场地向上为正**，场地地面 Z = 0 |
| X 范围 | 0 – 2400 mm |
| Y 范围 | 0 – 2400 mm |
| 姿态角 θ | 绕 Z 轴，从 +X 转向 +Y 为**正（逆时针）** |

> ⚠️ **"左下角"的具体物理位置必须在场地实测时确认并拍照记录**（站在哪个方向看）。
> 建议：**以二维码板所在的那条边为基准**确定方向，因为二维码板位置相对固定。
> **一旦确定，写入 [../05-场地与标定/场地尺寸实测绘.md](../05-场地与标定/场地尺寸实测绘.md) 并配图。**

### 2.2 机器人坐标系 R（Robot）

```
        机器人俯视图
             Y_r ↑
                  │
        ┌─────────┼─────────┐
        │         │         │
        │         ●─────────┼──► X_r
        │      原点(旋转中心)│
        │                   │
        └───────────────────┘
```

| 项 | 定义 |
|---|---|
| 原点 | 底盘**旋转中心**（差速/麦轮的理论旋转中心，通常为几何中心）在地面的投影 |
| **X_r 轴** | **机器人正前方** |
| **Y_r 轴** | **机器人左侧**（从上方看，X 轴逆时针转 90°） |
| **Z_r 轴** | **向上为正** |
| 姿态角 θ_r | 机器人在场地坐标系中的朝向，θ_r = X_r 与 X_F 的夹角，逆时针为正 |

> ⚠️ **X 向前、Y 向左** 是最常见的 ROS 约定（REP-103）。
> 若采用其他约定（如 Y 向右），**必须在此明确写出并全局统一**。
> **本队约定：X 向前，Y 向左，右手系。**

### 2.3 相机坐标系 C（Camera）

```
       光学中心为原点
       Z_c 沿光轴指向被拍摄物体
       
              Y_c ↑
                  │
                  │
                  ●──────► X_c
                 ╱
              Z_c (指向下方地面)
```

| 项 | 定义 |
|---|---|
| 原点 | 相机**光心** |
| **Z_c 轴** | 沿**光轴**，指向前方（即指向被拍摄的场地/地面） |
| **X_c 轴** | 图像**右方** |
| **Y_c 轴** | 图像**下方**（注意：相机坐标系通常 Y 向下） |
| 安装朝向 | **尽量垂直向下**（规则限制补光方向） |

> ⚠️ **相机坐标系 Y 轴通常向下**，这与机器人坐标系 Y 向左**不同**。
> **这是坐标转换最容易出错的地方。**
>
> 垂直向下安装时：`Z_c` 指向地面（即世界 `-Z_F` 方向）。
> 因此从相机坐标转换到机器人坐标需要一次**绕 X 轴旋转 90°**（或 -90°，取决于具体安装）。

### 2.4 机械臂基座坐标系 A（Arm Base）

| 项 | 定义 |
|---|---|
| 原点 | 机械臂**基座旋转中心**在安装面的投影 |
| **X_a 轴** | **与机器人 X_r 平行同向**（即机器人正前方）|
| **Y_a 轴** | **与机器人 Y_r 平行同向**（即机器人左侧）|
| **Z_a 轴** | 沿基座旋转轴**向上为正** |

> 💡 **约定 A 与 R 轴平行**（只差平移）可以**大幅简化**后续计算。
> 若机械臂是倾斜安装的，则必须额外定义旋转矩阵，**并在本文件写明**。

### 2.5 像素坐标系 P（Pixel）

| 项 | 定义 |
|---|---|
| 原点 | 图像**左上角** |
| **u 轴** | 向右为正（列） |
| **v 轴** | 向下为正（行） |
| 单位 | 像素 |

### 2.6 工具坐标系 T（Tool / End-Effector）

| 项 | 定义 |
|---|---|
| 原点 | 夹爪**夹持中心**（两指中心，且在指端接触面位置） |
| 轴向 | 与末端法兰坐标系一致（待机械臂选型后确定） |
| 用途 | **放置点控制**：我们希望控制的是这个点的位置，不是法兰 |

> ⚠️ **放置精度 ≤ ±1.5 mm 是针对工具坐标系 T 的要求**，不是法兰或臂末端。**标定时必须标到 T。**

## 3. 坐标变换链

### 3.1 视觉目标 → 机器人动作

```
  像素坐标 (u, v)
        │
        │  ① 相机内参（标定得到）
        ▼
  相机坐标 (X_c, Y_c, Z_c)
        │
        │  ② 手眼标定矩阵  T_R←C
        ▼
  机器人坐标 (X_r, Y_r, Z_r)
        │
        │  ③ 里程计/定位：T_F←R
        ▼
  场地坐标 (X_F, Y_F, Z_F)
        │
        │  ④ 决策：目标点
        ▼
  机器人坐标下的目标点
        │
        │  ⑤ 逆运动学
        ▼
  机械臂关节角 / 底盘速度指令
```

### 3.2 变换矩阵约定

**统一使用 4×4 齐次变换矩阵**：

```
        ┌                ┐
        │ R(3×3)  t(3×1) │
  T  =  │                │
        │ 0  0  0    1   │
        └                ┘
```

| 记号 | 含义 |
|---|---|
| `T_R←C` | **把相机坐标系的点变换到机器人坐标系**（读作 "T from C to R"） |
| `T_F←R` | 把机器人坐标变换到场地坐标 |
| `T_T←R` | 工具坐标系在机器人坐标系中的位姿 |

> ⚠️ **下标约定必须统一为 `T_目标←源`**，即 `p_目标 = T_目标←源 · p_源`。
> 反向变换为矩阵求逆。**这个约定不一致是最隐蔽的 bug 来源。**

### 3.3 简化前提（垂直向下安装时）

若相机**严格垂直向下**安装在机器人上，且相机 X_c 轴与机器人 X_r 轴对齐：

```
Z_c 指向地面  →  Z_c = -Z_r 方向
X_c 对齐 X_r  →  X_c = +X_r
Y_c 向下      →  Y_c = -Y_r（因为 Y_r 向左）

因此：   X_r = +X_c
        Y_r = -Y_c
        Z_r = -Z_c + h_cam      (h_cam = 相机光心离地高度)
```

> ⚠️ 上式中 **`Y_r = -Y_c`** 的负号是最容易漏掉的。
> **本节内容必须在实物上验证**（放一个标记物，看像素移动方向与机器人坐标是否一致）。

### 3.4 相机内参标定

| 参数 | 符号 | 说明 | 状态 |
|---|---|---|---|
| 焦距（x） | f_x | 像素 | ⬜ |
| 焦距（y） | f_y | 像素 | ⬜ |
| 主点（x） | c_x | 像素 | ⬜ |
| 主点（y） | c_y | 像素 | ⬜ |
| 径向畸变 | k1, k2, k3 | — | ⬜ |
| 切向畸变 | p1, p2 | — | ⬜ |

**标定方法**：棋盘格标定板（建议 ≥ 8×6 内角点），采集 ≥ 20 张不同位姿图像，用 OpenCV `calibrateCamera`。

**标定结果存放**：`vision/calibration/camera_intrinsics.yaml`

### 3.5 手眼标定

| 项 | 说明 |
|---|---|
| 问题 | 求 `T_R←C`（相机在机器人上的安装位姿） |
| 方法 | 若相机固定于机器人本体 → **eye-in-hand**（或更准确说：相机与机器人一起运动，标定相机↔底盘） |
| 数据 | 让机器人运动到 ≥ 10 个不同位姿，观察场地固定标记的像素坐标变化 |
| 工具 | OpenCV `calibrateHandEye`（需机械臂有已知正向运动学） |

**标定结果存放**：`vision/calibration/hand_eye.yaml`

> ⚠️ **手眼标定结果一旦改变（相机被撞、拆装），必须重新标定并更新此文件 + 记录版本。**
> 建议在标定结果文件中写入**标定日期和标定人**，并在 [../30-实验记录/](../30-实验记录/) 留档。

## 5. 标定流程（现场 3 分钟调试内的要求）★

> ⚠️ **这是最容易被忽视、但直接决定比赛成败的部分。**
> 每轮只有 **3 分钟调试**，且「比赛中（含调试）不能更换任何零部件」。
> 场地有偏差、二维码板位置随机、圆环位置有偏差。
> **如果标定需要 10 分钟，那你们每轮都只能拿低分。**

### 5.1 标定项清单

| # | 标定项 | 依赖 | 是否每轮必须 | 目标耗时 |
|---|---|---|---|---|
| 1 | 相机内参 | 相机 | ❌ 一次即可 | — |
| 2 | 手眼标定 | 相机安装 | ⚠️ 拆装后 | ≤ 30 s |
| 3 | 场地原点/朝向 | 场地 | ✅ 每轮 | ≤ 20 s |
| 4 | 启停区位置 | 场地 | ✅ 每轮 | ≤ 10 s |
| 5 | 圆环坐标 | 场地 | ✅ 每轮 | ≤ 30 s |
| 6 | 转盘中心 | 场地 | ✅ 每轮 | ≤ 10 s |
| 7 | 颜色阈值/白平衡 | 光照 | ✅ 每轮 | ≤ 20 s |
| 8 | 二维码识别参数 | 光照 | ⚠️ 视情况 | ≤ 10 s |
| **合计** | | | | **≤ 130 s** |

> ⚠️ 3 分钟 = 180 秒，标定要控制在 **130 秒内**，留 50 秒做**动作验证**（试抓一次/试放一次）。

### 5.2 标定方式选择

| 方案 | 优点 | 缺点 | 建议 |
|---|---|---|---|
| **手动示教**（遥控/按键推动机械臂到目标点并记录） | 简单可靠 | 慢，占用调试时间 | ⚠️ 但**规则禁止遥控**！注意：调试期间是否允许示教需澄清 |
| **视觉自动识别场地标记** | 快，无需人工 | 依赖视觉鲁棒性 | ✅ **推荐** |
| **预存多套参数**（按场地号） | 最快 | 场地布置有随机性，不完全可靠 | ⚠️ 辅助手段 |
| **场地物理基准**（用机械限位/触碰对刀） | 精确 | 需额外机构 | ✅ 可与视觉互补 |

> ⚠️ **重要合规问题**：「不允许任何方式的遥控」是否包括**调试期间的手动示教**？
> 规则表述为"比赛过程中"不允许遥控。**调试期间的人工调整通常是允许的**，但
> **"运行过程中不能触碰"**是明确的。
> → **此问题必须向裁判确认**（已登记在 [../00-规则与命题/合规检查表.md](../00-规则与命题/合规检查表.md) 第八部分）。

### 5.3 推荐方案：视觉自动标定

```
标定流程（目标 < 130 s）：
  1. 机器人放在启停区，一键进入"标定模式"
  2. 相机垂直向下拍摄，自动识别：
     - 车道边界（灰/白分界）→ 推算场地坐标系
     - 圆环（同心圆 + 数字）→ 推算 1-6 环坐标
     - 转盘（圆形 + 物料）→ 推算转盘中心
  3. 自动保存标定结果到参数文件
  4. 显示标定成功/失败与残差
  5. 人工目视确认（≤ 20 s）
```

**标定质量控制**：
- [ ] 标定后显示**残差**（如圆环定位残差 ≤ 1 mm）
- [ ] 残差过大时**报警**而不是静默使用
- [ ] 标定结果**保存到文件**（便于复盘和复用）

### 5.4 标定失败降级

| 情形 | 降级策略 |
|---|---|
| 圆环识别失败 | 用**上次标定值 + 局部搜索** |
| 场地整体偏差大 | 用**相对定位**（以启停区为基准推算） |
| 视觉完全不可用 | ⚠️ 准备**纯机械/里程计方案**作为兜底（但精度会差） |

## 6. 单位与精度约定

| 量 | 存储类型 | 单位 | 精度 | 范围 |
|---|---|---|---|---|
| 位置 | `int16` | mm | 1 mm | ±32767 |
| 高精度位置（标定用） | `int32` | μm | 1 μm | — |
| 角度（传输） | `int16` | 0.01° | 0.01° | ±327.67° |
| 角度（内部计算） | `float64` | rad | — | — |
| 速度（线） | `int16` | mm/s | 1 mm/s | ±32767 |
| 速度（角） | `int16` | 0.01°/s | 0.01°/s | ±327.67°/s |
| 时间 | `uint32` | ms | 1 ms | — |

> ⚠️ **角度传输用 0.01° 整数**，避免浮点跨平台差异。
> **内部计算用弧度**，仅在通信边界转换。

### 6.1 精度要求（来自评分推导）

| 量 | 要求 | 来源 |
|---|---|---|
| **落点（工具坐标系 T）重复精度** | **≤ ±1.0 mm**（目标），必须 ≤ ±1.5 mm | 1 环要求 |
| 底盘定位精度 | ≤ ±20 mm | 需靠臂补足 |
| 相机测量精度（工作距离处） | ≤ ±1 mm | 支撑落点要求 |
| 圆环定位精度 | ≤ ±1 mm | 同上 |
| 里程计累计误差（3 min） | ≤ 2% | 影响回启停区 |

> ⚠️ **底盘定位精度（±20 mm）远达不到落点要求（±1.5 mm）**，
> 因此**必须有机械臂末端的二次精定位**（视觉伺服 / 触碰定位 / 柔性导向）。
> 这是本项目的核心技术决策。→ 登记为 ADR。

## 7. 常见错误检查表（评审时逐条核对）

| # | 易错点 | 检查方法 |
|---|---|---|
| 1 | 单位混用 mm/cm/m | 全局搜索 `cm`、`/ 1000`、`* 1000` |
| 2 | 角度正方向不一致 | 单元测试：正角度应逆时针 |
| 3 | 相机 Y 轴方向搞反 | 实物验证：物体向右移，X_r 应增大 |
| 4 | 变换矩阵下标方向搞反 | 检查 `T_A←B · T_B←A == I` |
| 5 | 右手系 vs 左手系 | 检查 `X × Y == Z` |
| 6 | 端点 vs 中心定义不一致 | 明确"坐标"指几何中心还是角点 |
| 7 | 像素坐标 v 轴方向 | 确认图像原点在左上 |
| 8 | 畸变未校正 | 标定后检查直线是否变直 |
| 9 | 工具坐标系未标到夹持中心 | 实测：放置一个物料，量偏差 |
| 10 | 标定参数未版本化 | 检查标定文件含日期与标定人 |
| 11 | 硬编码场地坐标 | 全局搜索是否可直接改参数而无需重编译 |
| 12 | 浮点累积误差 | 长时间运行后检查位置漂移 |
