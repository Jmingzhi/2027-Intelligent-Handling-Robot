# 实验记录

> **文档定位**：本目录存放**每一次实验的完整记录**。
> 团队纪律第 4 条："所有实验**必须**留记录"。
>
> > ⚠️ **原始数据比结论重要。**
> > 结论会被后来的实验推翻，但原始数据永远可以重新分析。
> > 一条只写"实验成功、精度达标"的记录，在赛后复盘时**没有任何价值**。
>
> **关联**：[实验记录模板.md](../90-模板/实验记录模板.md) · [测试用例模板.md](../90-模板/测试用例模板.md) · [待确认清单.md](../60-项目管理/待确认清单.md) · [风险登记.md](../60-项目管理/风险登记.md)

---

## 1. 为什么要写实验记录

| # | 理由 | 说明 |
|---|---|---|
| 1 | **可复现** | 三个月后的你，不会记得当时的参数和现象 |
| 2 | **可追溯** | 当结论变化时，能查到是哪个实验推翻的 |
| 3 | **防止重复劳动** | 避免"这个我们好像测过？"的浪费 |
| 4 | **支撑设计决策** | ADR 的依据来源需要实验数据（见 [ADR模板.md](../90-模板/ADR模板.md) 3.2 节） |
| 5 | **发现退化** | 与历史数据对比，能发现性能退化 |
| 6 | **答辩材料** | 设计说明书需要实测数据支撑 |

> 💡 **三人队最贵的资源是时间**。一次没有记录的实验 = 一次必然要重做的实验。

## 2. 编号规则

### 2.1 命名格式

```
YYYYMMDD-序号-主题.md
```

| 部分 | 说明 | 示例 |
|---|---|---|
| `YYYYMMDD` | 实验日期 | `20270215` |
| `序号` | 当天第几次实验，两位数字 | `01`、`02`、`03` |
| `主题` | 简短中文主题，用连字符或直接中文 | `落点精度重复性` |

**示例**：

```
20270215-01-底盘重复定位精度.md
20270215-02-圆环视觉定位残差.md
20270218-01-转盘转速实测.md
20270301-01-浅蓝与蓝区分度.md
```

### 2.2 编号纪律

| # | 纪律 |
|---|---|
| 1 | 日期必须是**实际实验日期**，不是写记录的日期 |
| 2 | 序号**当天连续**，不复用 |
| 3 | 主题要**能看出测了什么**，不要写"实验1""测试" |
| 4 | 一次实验一个文件，不要把多次实验塞进一个文件 |
| 5 | 实验**失败也要记录**（失败记录往往更有价值） |

> ⚠️ **不要用"实验A""测试2"这种命名**。半年后没人知道那是什么。

### 2.3 相关问题

| 情形 | 处理 |
|---|---|
| 同一天多次实验 | 序号递增 `01` `02` `03` |
| 跨天连续实验 | 各自按日期建文件，在"关联"中互相引用 |
| 修正已发布的记录 | ⚠️ **不删除原内容**，在文末"变更历史"中追加修正说明 |
| 实验作废 | ⚠️ **不删除**，在文件顶部标注"⚠️ 本实验作废，原因：……" |

> ⚠️ **实验记录一经写入不删除**。
> 删除记录等于抹掉"我们曾经这么想过"，这在复盘时是最有价值的信息。

## 3. 存放位置

```
docs/30-实验记录/
├── README.md                         本文件
├── 20270215-01-底盘重复定位精度.md
├── 20270215-02-圆环视觉定位残差.md
├── 20270218-01-转盘转速实测.md
└── attachments/                       原始数据、图片、日志（可选）
    ├── 20270215-01-落点数据.csv
    └── 20270215-01-现场照片.jpg
```

| 内容 | 位置 | 说明 |
|---|---|---|
| 实验记录正文 | `docs/30-实验记录/*.md` | 本目录 |
| 原始数据（CSV/日志） | `docs/30-实验记录/attachments/` 或就近存放 | 建议就近，便于查找 |
| 大文件（视频） | Git LFS 或外链 | 见 `.gitattributes` |
| 测试用例 | `test/<类别>/` | 与实验记录互相引用 |
| 实验模板 | `docs/90-模板/实验记录模板.md` | 复制使用 |

> 💡 附件较多时，可按实验编号建子目录，避免目录过于杂乱。

## 4. 必须包含的内容

> 完整字段见 [实验记录模板.md](../90-模板/实验记录模板.md)。以下是**最低要求**：

| # | 内容块 | 为什么必需 |
|---|---|---|
| 1 | **实验编号、日期、地点、参与人** | 可追溯 |
| 2 | **实验目的** | 没有目的的实验是浪费 |
| 3 | **实验条件**（硬件/固件/软件版本 + Git 提交号 + 环境条件） | ★ 缺少版本号的数据**不可比较** |
| 4 | **实验步骤** | 可复现 |
| 5 | ★ **原始数据** | **核心**，不可只写结论 |
| 6 | **数据处理与分析** | 说明统计方法、异常点处理理由 |
| 7 | **结论** | 与预设判据对照 |
| 8 | **是否改变原有结论** | 影响其他文档的触发器 |
| 9 | **遇到的问题** | 暴露风险 |
| 10 | **关联 Issue** | 问题要跟踪 |
| 11 | **下一步** | 有负责人与期限 |

### 4.1 关于"原始数据必须保留"

| ❌ 不充分的写法 | ✅ 充分的写法 |
|---|---|
| "测量了 10 次，精度达标" | 列出 10 次的具体数值 + 均值/标准差 + 原始 CSV 附件 |
| "图片识别效果良好" | 给出混淆矩阵 + 失败样本的图像 |
| "耗时约 5 秒" | 给出 N 次计时的逐个数值 |
| "运行正常" | 给出日志文件 + 关键指标 |

> ⚠️ **判断标准**：别人拿到你的记录，**能否重新算出你的结论**？
> 不能 → 数据不充分。

### 4.2 关于版本信息

| 项 | 获取方式 |
|---|---|
| Git 提交号 | `git rev-parse HEAD` |
| 当前分支 | `git branch --show-current` |
| 是否有未提交改动 | `git status --short`（★ 有改动必须说明改了什么） |
| 固件版本 | 固件中定义的版本号 |
| 模型版本 | `vision/models/` 中的文件名或版本记录 |

> ⚠️ **"有未提交改动"必须写明**。否则别人 checkout 同一个提交号也复现不出来。

## 5. 与 Issue 的关联方式

### 5.1 关联方向

```
   实验记录  ──────►  Issue       （实验中发现的问题）
       ▲                │
       │                │
       └────────────────┘         （Issue 要求做的验证实验）
```

| 场景 | 做法 |
|---|---|
| 实验中发现新问题 | **建 Issue**，在实验记录"关联 Issue"填编号 |
| Issue 要求做某个验证 | 在 Issue 中评论实验记录的文件路径 |
| 实验推翻了某结论 | 建 Issue 追踪受影响文档的更新（见模板 6.1 节） |
| 实验证实了某假设 | 在相关 Issue 中关闭并引用实验记录 |

### 5.2 关联写法

| 位置 | 写法 |
|---|---|
| 实验记录 → Issue | `关联 Issue：#42` |
| Issue → 实验记录 | `验证结果见 docs/30-实验记录/20270215-01-底盘重复定位精度.md` |
| 实验记录 → ADR | `关联 ADR：ADR-0002` |
| PR → 实验记录 | 见 [PR描述模板.md](../90-模板/PR描述模板.md) 3.2 节 |

> 💡 **实验记录是"证据"，Issue 是"待办"**。
> 两者都要有：只写实验记录，问题会丢；只写 Issue，没有依据。

## 7. 实验记录质量自检

> 每次写完记录，对照此表自检。

- [ ] 文件命名符合 `YYYYMMDD-序号-主题.md`
- [ ] 日期是实际实验日期
- [ ] 版本信息完整（硬件/固件/软件/Git 提交号）
- [ ] 有未提交改动时已说明
- [ ] 环境条件已记录（温度/地面/光照等）
- [ ] **原始数据完整保留**，不是只有结论
- [ ] 附件路径有效
- [ ] 统计方法已说明，异常点剔除有理由
- [ ] 结论与预设判据对照
- [ ] "是否改变原有结论"已填写
- [ ] 关联 Issue 已建立或链接
- [ ] 目录索引表已更新
- [ ] 下一步有负责人与期限
