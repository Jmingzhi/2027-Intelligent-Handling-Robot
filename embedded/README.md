## 编码约束（★重要）

| # | 约束 | 原因 |
|---|---|---|
| 1 | **所有变量名或注释必须标明单位** | 三人队最常见 bug 就是 mm/m 混用 |
| 2 | **禁止魔法数字** | 必须定义为有名字的常量，便于调参 |
| 3 | **所有等待必须有超时** | ★规则：机器人停止运行 15 秒本轮结束 |
| 4 | **中断服务函数尽量短** | 禁止阻塞、延时、打印 |
| 5 | **跨中断访问的全局变量必须 `volatile`** | 否则编译器优化导致行为异常 |
| 6 | **通信协议必须引用 `shared/`** | 禁止复制粘贴协议定义 |
| 7 | **现场可标定参数不得硬编码** | 场地有偏差，且以现场为准 |
| 8 | **结构化日志** | 赛后复盘与时间剖面分析依赖它 |

## 关键逻辑要求（来自规则）

| 要求 | 说明 |
|---|---|
| **物料未上机不得移动** | 规则：「物料没有放置到搬运机器人上不能向下一个区域运行」→ 必须有料仓在位确认 |
| **禁止夹持运送** | 规则：「不允许用手爪夹持物料运送」→ 抓取后必须放入本体料仓 |
| **落点一次到位** | 规则：「物料底面一旦与地面接触即视为放置完毕…若再次移动此物料，本轮比赛结束」→ **软件不得有"放置后微调"逻辑** |
| **无遥控功能** | 规则：「不允许任何方式遥控」→ 调试通道只能读日志/写参数，不能控制动作 |
| **车体投影留在车道内** | 规则：铅垂投影越界（机械臂除外）→本轮结束 |
| **实时统计** | 抓取正确次数与放置正确次数必须与裁判判定一致 |
