# 算法

> 路径规划、定位、任务状态机中与视觉无关的算法部分。

## 本目录与 `vision/` 的分工

| 目录 | 负责 |
|---|---|
| `vision/` | **感知**：从图像得到"物料在哪、什么颜色、圆环在哪、二维码内容" |
| `algorithm/` | **决策**：拿到感知结果后，"去哪里、怎么走、先抓哪个、放到哪" |

> 💡 边界要清晰。**感知层不做决策，决策层不碰像素。**

## 待实现内容

| 模块 | 职责 | 状态 |

| 任务码解析 | 解析 `156+123+516+231` → 结构化任务 | ⬜ |

| 标定算法 | 从视觉结果推算场地坐标系与圆环坐标 | ⬜ |

## ⚠️ 本项目的算法难点

| 难点 | 说明 |
|---|---|
| **节拍优化** | 3 分钟约 19–20 个动作点，平均每动作仅 9 秒。必须按 150 s 设计 |
| **转盘等待"藏"起来** | ★规则：静止 15 秒本轮结束。**不能傻等转盘**，要把等待时间放在"去读二维码"的路径里 |
| **抓取顺序** | 顺应转盘转向可显著减少等待 |
| **精度补偿** | 底盘定位精度只能到 ±20 mm，落点要求 ±1.5 mm → 必须靠机械臂末端二次定位 |
| **路径边界** | 车道宽 400 mm，车体投影越界即结束 → 必须留安全余量（建议 ≥40 mm） |
| **统计口径** | 顺序错误、位置错误的都不能计入"正确"；必须与放置判定共用状态机 |

## 编码要求

| 项 | 要求 |
|---|---|
| 单位 | **变量名带单位**（`target_x_mm`） |
| 参数 | 禁止硬编码场地坐标，必须可现场标定 |
| 超时 | 每个状态必须有超时（≤3 s 级） |
| 日志 | 结构化输出，用于时间剖面分析 |
| 测试 | 任务码解析等纯逻辑必须有单元测试 |
