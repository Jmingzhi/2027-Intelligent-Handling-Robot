# 购件合规台账

> ## ⚠️ 本目录存在的唯一理由
>
> 规则原文：
> > 「除**标准件**外，非标零件应**自主设计和制造**，**不允许使用购买的成品或采用成品套件拼装而成**。」
> >
> > 「如果不符合上述各项要求，**取消比赛资格**；若已经参赛，发现或投诉并情况属实**取消比赛成绩**。」
>
> **这是本赛项最容易"不知不觉违规"的地方。** 本台账的目的就是：**让每一个零件的合规性都有据可查。**

---

## 1. 判定原则

| 类别 | 是否允许购买 | 说明 | 例 |
|---|---|---|---|
| **标准件** | ✅ 允许 | 通用规格件，非为本机专门设计 | 螺钉、螺母、垫圈、轴承、卡簧、销、弹簧、标准齿轮、同步带、链条、型材、光轴、直线轴承、联轴器、标准舵机、标准电机、标准传感器模块 |
| **成品套件 / 成品模块** | ❌ **禁止** | 买来直接用或拼装 | 成品机器人底盘、成品机械臂、成品套件车、成品抓取模块 |
| **非标结构件** | ❌ **禁止购买，必须自制** | 为本机专门设计的结构件 | 底板、支架、连接件、夹爪、料仓、外壳、转接件 |
| **标准件改制的非标件** | ⚠️ 需评估 | 在标准件基础上自行加工 | 需保留加工记录与照片 |

---

## 2. 灰色地带（必须向裁判确认后再采购）

> ⚠️ 以下情形**不要自己判断**。先登记为 `⚠️待确认`，向裁判/组委会书面询问，得到答复后再采购。

| 情形 | 风险判断 | 建议 |
|---|---|---|
| 成品**金属舵机支架** | ⚠️ **高风险** —— 通常属于非标结构件 | 尽量自制（3D 打印/加工）；若必须用，保留证据说明是通用标准配件 |
| 成品**履带 / 轮胎** | ✅ 通常视为标准件 | 保留购买记录 |
| 成品 **PCB 模块**（电机驱动板、降压模块） | ⚠️ 需评估 | 电控模块一般可接受，但**自制 PCB 也有利于创意分** |
| 成品**码盘 / 编码器** | ✅ 标准件 | — |
| 成品**丝杆 + 螺母副** | ✅ 标准件 | — |
| 成品**同步带轮** | ✅ 标准件 | — |
| **开源项目的 3D 打印件图纸** | ⚠️ **高风险** —— 不属于"自主设计" | **必须自己重新设计**，不要直接下载打印 |
| 成品**亚克力切割件** | ❌ 非标结构件 | 自行设计并加工 |
| **3D 打印服务代打**（自己设计） | ✅ 合规 —— 设计是自己的 | 保留设计文件（.stl/.step）与打印记录 |
| 成品**舵机控制板** | ⚠️ 需评估 | 电控模块，建议评估后记录依据 |

## 5. 证据保留要求

| 零件类型 | 必须保留的证据 |
|---|---|
| 自制-3D 打印 | 设计源文件（.SLDPRT/.step/.f3d）+ 打印参数 + 实物照片 |
| 自制-机加工 | 设计图（工程图）+ 加工照片 + 加工记录 |
| 自制-激光切割 | 设计文件 + 切割照片 |
| 标准件-外购 | 购买订单截图 + 商品页面（证明是通用规格件） |
| 成品模块 | 购买记录 + **裁判书面答复**（若有） |
| ⚠️待确认 | 询问记录 + 答复 |

**证据存放位置**：

```
hardware/compliance/
├── README.md           # 本文件
├── compliance.csv      # 机读台账
└── evidence/           # 证据文件
    ├── 自制件照片/
    ├── 订单截图/
    └── 裁判答复/
```

## 6. 与 BOM 的对应关系

> ⚠️ **`hardware/bom/BOM.csv` 的"来源"列必须与本台账一致。**

| BOM 字段 | 对应本台账 |
|---|---|
| 来源 | 来源判定 |
| 合规判定依据 | 判定依据 |

**一致性检查（计划做成脚本 `tools/check_compliance.py`）**：

- [ ] BOM 中每个零件的"来源"都在允许取值范围内
- [ ] BOM 中标注自制的零件都在本台账有登记
- [ ] BOM 中标注"标准件-外购"的都有"合规判定依据"
- [ ] 没有取值为 `⚠️待确认` 的零件进入装配阶段

## 7. 采购前检查流程

```
① 确认这个零件是"标准件"还是"非标件"
       │
       ├── 标准件 → 可以直接采购 → 登记台账（判定依据 + 订单截图）
       │
       └── 非标件 → 必须自制（3D 打印/加工）
                    → 登记台账（设计源文件 + 照片）
                    
       灰色地带 → 登记为 ⚠️待确认 → 问裁判 → 得到答复 → 再决定
```

**采购前必做：**

- [ ] 对照 [../../docs/00-规则与命题/合规检查表.md](../../docs/00-规则与命题/合规检查表.md) 第一部分
- [ ] 该零件已在本台账登记
- [ ] 若是灰色地带，已向裁判确认并留存答复
- [ ] 已加入 `hardware/bom/BOM.csv`（且「来源」列与本台账**逐条一致**）

## 7.1 ⚠️ 待确认项必须在赛前清零

> ⚠️ **`⚠️待确认` 不是一种"状态"，而是一个"待办"。**

| 阶段 | 允许的 `⚠️待确认` 数量 |
|---|---|
| 设计探索期 | 不限 |
| 采购前 | 该零件必须已明确（不能带着 `⚠️待确认` 下单） |
| 装配前 | **应为 0** |
| **提交 / 参赛前** | **必须为 0** |

**清零流程**：

```
① 列出全部 ⚠️待确认 零件
        ▼
② 逐条向裁判/组委会书面提问
   （问题同时登记到 合规检查表.md 第八部分）
        ▼
③ 留存答复（书面/截图）到 evidence/裁判答复/
        ▼
④ 答复为"允许" → 更新来源判定 + 判定依据
   答复为"不允许" → 改为自制方案，重新设计并加工
        ▼
⑤ 同步更新 hardware/bom/BOM.csv 的「来源」列
        ▼
⑥ 复查：⚠️待确认 数量 = 0
```

> ⚠️ 赛前仍为 `⚠️待确认` 的零件，视为**风险**，应登记到
> [../../docs/60-项目管理/风险登记.md](../../docs/60-项目管理/风险登记.md)，
> 并在赛前评审中作为阻塞项处理。

## 7.2 关于"开源图纸"的特别说明

| 情形 | 判定 | 说明 |
|---|---|---|
| 直接下载开源 `.stl` 打印使用 | ❌ **违规** | 非"自主设计" |
| 参考开源设计思路，**自己重新建模** | ✅ 合规 | 设计是自己的 |
| 使用开源**算法 / 代码** | ✅ 合规 | 规则约束的是**零件**，不是软件 |
| 使用开源**电路设计**自行打板 | ✅ 合规 | 需确认该设计可自由使用 |

> ⚠️ **"参考思路"与"照抄图纸"的界线**：判据是**有没有你自己的设计过程**
> （有自己的 CAD 文件、自己的尺寸决策）。
> 保险做法：**从头建模，不要导入他人的模型文件**。

## 7.3 台账字段取值约束（★ 重要）

> ⚠️ 第 3 节列出的 `成品模块` 取值**仅供"已购买并已留存裁判答复"的历史情况使用**。
> **任何新的采购都不允许产生 `成品模块` 条目**——
> 成品模块属于规则明文禁止项（见第 1 节）。
>
> 新登记的零件，`来源判定` 只应在下面四类中取值：

| 取值 | 含义 | 允许 |
|---|---|---|
| `自制-3D打印` | 自主设计 + 3D 打印（含外协代打） | ✅ |
| `自制-机加工` | 自主设计 + 机加工 | ✅ |
| `自制-激光切割` | 自主设计 + 激光切割 | ✅ |
| `标准件-外购` | 符合第 1 节标准件定义 | ✅ |
| `⚠️待确认` | 灰色地带，待澄清 | ⚠️ **临时，赛前必须清零** |

> 💡 字段定义与登记规则另见 [../../docs/90-模板/BOM登记模板.md](../../docs/90-模板/BOM登记模板.md)，
> 该模板说明了 BOM 的「来源」列如何与本台账对应。

## 8. 为什么要这么麻烦

这个赛项的设计意图是**考察自主设计与制造能力**，因此对"买成品"极其严格。
往届有队伍因为使用了成品底盘或成品套件而被取消资格。

**判断标准很简单**：

> ## 「这个零件，是我们自己设计并做出来的吗？」
> - 是 → 合规（保留证据）
> - 不是，但它是螺丝/轴承/标准舵机这类通用规格件 → 合规（记录判定依据）
> - 不是，且它是为本机专门设计的结构件 → **违规**
