# 标定文件

> ⚠️ **本目录的文件直接影响落点精度。** 相机被撞、拆装后**必须重新标定并更新**。

## 需要的标定文件

| 文件 | 内容 | 何时重标 |
|---|---|---|
| `camera_intrinsics-YYYYMMDD.yaml` | 相机内参（fx, fy, cx, cy, k1,k2,k3,p1,p2） | 相机更换/改动焦距 |
| `hand_eye-YYYYMMDD.yaml` | 手眼标定（相机相对机器人的位姿 `T_R←C`） | ★相机拆装、被撞后 |
| `field-YYYYMMDD.yaml` | 场地标定（原点、朝向、圆环坐标、转盘中心） | ★每轮比赛现场 |
| `color_profile-YYYYMMDD.yaml` | 颜色参考（各色采样值、白平衡参数） | ★每轮比赛现场 |

## 文件命名与内容要求

**命名**：`类型-YYYYMMDD.yaml`（多份则加序号）

**每个标定文件必须包含**：

```yaml
# 标定元信息 —— 必须填写
meta:
  type: camera_intrinsics       # 标定类型
  date: 2027-03-15              # 标定日期
  operator: ""                  # 标定人
  git_commit: ""                # 代码版本
  equipment: ""                 # 相机型号等
  notes: ""                     # 备注

# 标定结果
data:
  # ...具体参数

# 标定质量
quality:
  residual_mm: 0.0              # 残差（越小越好）
  samples: 0                    # 样本数
  verified: false               # 是否经实物验证
```

> ⚠️ **没有元信息的标定文件等于废纸** —— 无法追溯、无法判断是否过期。

## 标定质量要求

| 标定项 | 指标 | 要求 |
|---|---|---|
| 相机内参 | 重投影误差 | < 0.5 像素 |
| 手眼标定 | 位置残差 | < 1 mm |
| 场地标定 | 圆环定位残差 | **< 1 mm** |
| 颜色标定 | 6 色区分度（最小类间距离） | 需专门验证浅蓝 vs 蓝 |

**残差过大必须报警，不得静默使用。**

## 现场标定的时间预算（★关键）

> 每轮只有 **3 分钟调试**时间，且「比赛中（含调试）不能更换任何零部件」。

| 标定项 | 目标耗时 | 是否每轮必须 |
|---|---|---|
| 手眼标定 | ≤ 30 s | 仅拆装后 |
| 场地原点/朝向 | ≤ 20 s | ✅ |
| 启停区位置 | ≤ 10 s | ✅ |
| 圆环坐标 | ≤ 30 s | ✅ |
| 转盘中心 | ≤ 10 s | ✅ |
| 颜色/白平衡 | ≤ 20 s | ✅ |
| **合计** | **≤ 130 s** | 留 50 s 做动作验证 |

> ⚠️ **如果标定需要 10 分钟，你们每轮都只能拿低分。**
> 必须实现**视觉自动标定**，并反复演练。

详见 [../../docs/10-接口契约/坐标系与标定约定.md](../../docs/10-接口契约/坐标系与标定约定.md) 第 5 节。

## ⚠️ 注意事项

- 标定文件**必须入库**（体积小，且是关键参数）
- 但**不要提交带个人信息的路径**（如 `C:\Users\张三\...`）
- 标定结果变化时，**在 [../../docs/30-实验记录/](../../docs/30-实验记录/) 留档**
- 标定文件与代码版本要能对应（记录 `git_commit`）
