## 一、这个仓库是什么

这是本队参加 **2027 年第十届中国大学生工程实践与创新能力大赛「智能搬运」赛项** 的工程仓库，用来集中管理：

- **规则与合规**：官方命题原文、规则解读、合规自查（哪些能买、哪些必须自制）
- **接口契约**：机械/电气/软件的对接约定（坐标系、通信协议、尺寸接口）
- **机械与硬件**：CAD 模型、电路设计、BOM、加工图、购件合规台账
- **嵌入式与控制**：主控固件、通信协议实现
- **视觉与算法**：相机标定、识别、定位、路径规划、任务调度
- **测试与验收**：台架测试、场地测试、按官方评分项自测
- **决策与项目管理**：架构决策记录、里程碑、风险登记、待确认清单

> **一句话原则**：讨论可以在任何地方，**结论必须落回这个仓库**。

## 二、赛项核心约束速查

> 完整解读见 **[docs/00-规则与命题/规则解读.md](docs/00-规则与命题/规则解读.md)**。
> 下表是精简版，用于随时自检。

### 2.1 硬性红线（违反即取消资格或成绩）

| # | 约束 | 数值/要求 |
|---|---|---|
| 1 | **不允许购买成品或成品套件拼装** | 除标准件外，非标零件必须自主设计制造 |
| 2 | **机器人外形尺寸** | 铅垂投影 ≤ **300×300 mm**，高度 ≤ **400 mm**（含所有软质线路） |
| 3 | **机械臂可折叠** | 出发后方可展开，**展开后尺寸不受限** |
| 4 | **电源** | 只能 **1 个**装在机器人内部的电源，比赛中（含调试）**不能更换** |
| 5 | **禁止遥控** | 不允许任何形式的遥控；运行中不能触碰笔记本电脑 |
| 6 | **补光限制** | 不允许遮挡场地，**仅允许垂直向下补光** |
| 7 | **任务码显示装置** | 上部醒目位置、亮光、不被遮挡、**字高 ≥ 12 mm**、显示任务码与完成统计 |
| 8 | **一键启动** | 必须有明确标识的「启动」按钮，**只能有一个** |
| 9 | **文档匿名** | 提交文档中出现**校名/姓名/队名/电话/特殊符号 → 0 分**；**不得修改模板标题** |

### 2.2 场地与物料

| 项目 | 参数 |
|---|---|
| 场地 | **2400 × 2400 mm** 正方形 |
| 车道 | 灰色，十字车道宽 **400 mm**，中间对称四个淡黄区域 **450 × 450 mm** |
| 车道规则 | 离开启停区后**只能在灰色车道行驶**；铅垂投影越界（机械臂除外）→ 本轮结束 |
| 障碍物 | 黑色 φ50 × 100 mm，数量与位置**随机抽签** |
| 启停区 | 蓝色，**2 处**，300 × 300 mm |
| 原料区 | **φ300 mm 电动转盘**，总高 80–100 mm，放 3 个物料呈 **120°**，转速 **6–10 秒/圈**，转向随机 |
| 暂存区 / 粗加工区 | 580 × 150 mm，表面有测精度圆环，**线宽 1.5 mm** |
| 物料 | 3D 打印 **ABS/PLA**，尺寸 ≤ **80 mm**，重量 ≤ **100 g** |
| 物料颜色 | 红1 黄2 蓝3 绿4 黑5 浅蓝6（红黄蓝绿黑=ABS，浅蓝=PLA），**每色 2 个** |
| 二维码板 | A4 横放，二维码 **80 × 80 mm**（含边框），位置随机 |

### 2.3 放置精度评分（非线性，决定成败）

| 环号 | 1环 | 2环 | 3环 | 4环 | 5环 | 6环 | 6环外/倾倒 |
|---|---|---|---|---|---|---|---|
| **分数** | **15** | 10 | 7 | 5 | 3 | 1 | 0 |

- 判定方式：**物料底面能看到某个环的边缘 → 该物料在该环内**
- ⚠️ **物料底面一旦接触地面即视为放置完毕；若再次移动该物料 → 本轮比赛结束**（没有"微调"机会）

### 2.4 任务码格式

**4 组三位数，用 `+` 连接**：

```
  1 5 6  +  1 2 3  +  5 1 6  +  2 3 1
  └─┬─┘    └─┬─┘    └─┬─┘    └─┬─┘
第一批颜色顺序  第一批放置位置  第二批颜色顺序  第二批放置位置
```

- **颜色编号**：红1、黄2、蓝3、绿4、黑5、浅蓝6
- **位置编号**：1–6 号圆环
- 例：`156+123+516+231` = 第一批按红→黑→浅蓝抓取，分别放粗加工区1、2、3号环；第二批按黑→红→浅蓝，放粗加工区2、3、1号环

详见 **[docs/10-接口契约/任务码定义.md](docs/10-接口契约/任务码定义.md)**

### 2.5 时间账（最紧的约束）

| 环节 | 时间 |
|---|---|
| 每轮调试 | **3 分钟** |
| 调试剩 3 min | 抽签确定搬运任务 |
| 调试剩 30 s | 机器人停止运行，放回出发位；裁判摆二维码板、随机摆物料、启动转盘 |
| 每轮运行 | **3 分钟** |
| 出发后静止容忍 | **15 秒**（等待转盘转动时间增加 8 秒）→ 超时本轮结束 |
| 启动方式 | **一键启动，只有一次机会** |
| 轮次 | 每队 **2 次**运行机会，取最好成绩 |

### 2.6 成绩构成

```
初赛总成绩 = 任务命题文档 20% + 作品创意设计 10% + 现场初赛 70%
决赛总成绩 = 创新实践 30% + 现场决赛 70%
```

**现场初赛计分项**：

| 项 | 分值 |
|---|---|
| 正确读取二维码并显示任务码 | 1 分 |
| 每正确抓取 1 个物料（放到机器人上） | 2 分/个 |
| 粗加工区 + 暂存区平面放置准确度 | 15/10/7/5/3/1/0 每物料 ← **最大权重** |
| 暂存区码垛（第二批，颜色一致、不掉落） | 同放置分数 |
| 完成全流程按时回到启停区 | 2 分 |
| 正确显示抓取数量 + 放置数量 | 各 2 分 |

**作品创意设计（100 分）**：创新性 40 / 美观性 30 / 合理性 30
> 注：评分前提是「作品可以清晰观察到内部结构」——外观设计要**露内部**。

### 2.7 赛程时间线

| 时间 | 节点 |
|---|---|
| 2026-09-30 | 校赛预报名截止 |
| **2026-10 上旬** | **作品提交**（设计说明书、设计资料、答辩 PPT） |
| 2026-10 下旬 | 校赛评审（线下答辩 + 材料评审） |
| 2027-07 ~ 08 | 全国总决赛 |

## 五、快速开始（新队友 5 分钟上手）

完整版见 **[仓库管理手册.md](仓库管理手册.md)**，这里是极简版：

```bash
# 1. 克隆仓库
git clone <仓库地址>
cd 2027-Intelligent-Handling-Robot

# 2. 安装并启用 Git LFS（只做一次，非常重要）
git lfs install
git lfs pull

# 3. 确认身份
git config user.name   "你的名字"
git config user.email  "你的邮箱"

# 4. 开始工作前，先拉最新
git checkout develop
git pull

# 5. 为你的任务建分支
git checkout -b feature/你的任务名

# 6. 做完后提交
git add .
git commit -m "feat(机械): 新增抓手装配体"
git push -u origin feature/你的任务名
```

然后在 GitHub 上发起 **Pull Request** 到 `develop` 分支。

## 六、分支约定

| 分支 | 用途 | 规则 |
|---|---|---|
| `main` | **比赛稳定版本** | 只接受来自 `develop` 的合并；比赛前冻结，只修 Bug |
| `develop` | 日常开发集成 | 功能分支合并到此 |
| `feature/*` | 功能开发 | 从 `develop` 切出，完成后 PR 回 `develop` |
| `fix/*` | 紧急修复 | 可直接 PR 到 `main`（需 A 审核） |
| `release/*` | 参赛冻结版本 | 从 `develop` 切出，用于生成提交包 |

---

## 七、提交信息规范

格式：`<类型>(<范围>): <描述>`

| 类型 | 含义 |
|---|---|
| `feat` | 新增功能 |
| `fix` | 修复问题 |
| `docs` | 文档变更 |
| `test` | 测试相关 |
| `refactor` | 重构（不改行为） |
| `chore` | 杂项（配置、依赖） |
| `hw` | 硬件/机械变更 |
| `perf` | 性能优化 |

示例：
```
feat(vision): 实现二维码任务码解析
fix(embedded): 修正转盘抓取时序提前量
docs(接口契约): 补充坐标系转换约定
hw(cad): 抓手 V2 减轻 18g
```

**每次提交都应关联 Issue**：`feat(vision): 实现二维码解析 (#12)`

## 八、五条团队规则

1. 所有代码/模型修改**必须** Git 提交，不许只存在本地
2. 所有技术决策**必须**写入 [docs/50-决策记录/](docs/50-决策记录/)，避免反复推翻
3. 所有 Bug 与技术问题**必须**建 Issue
4. 所有实验**必须**留记录（用 [docs/90-模板/实验记录模板.md](docs/90-模板/实验记录模板.md)）
5. 比赛前**冻结 `main`**，只修 Bug
